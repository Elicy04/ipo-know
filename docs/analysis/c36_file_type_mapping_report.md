## 二、编码结构规律

`fileTypeMap` 可看作 `I + 四位数字`，其中：

### 1. 前两位表示“主类别”

| 前两位 | 主类别 |
|---|---|
| 00 | IPO 申报文件，包括招股说明书、审计报告、法律意见书、保荐书等 |
| 10 | 监管决定，如注册批复、终止审核决定 |
| 20 | 上市委审议会议文件 |
| 30 | 审核问询回复文件 |

### 2. 对于 `I00xx`，第 3 位表示文件类型，第 4 位表示披露阶段

例如：

| fileTypeMap | 第 3 位含义 | 第 4 位含义 |
|---|---|---|
| I0011 | 1 = 招股说明书 | 1 = 申报稿 |
| I0012 | 1 = 招股说明书 | 2 = 上会稿 |
| I0013 | 1 = 招股说明书 | 3 = 注册稿 |
| I0021 | 2 = 审计报告 | 1 = 申报版 |
| I0031 | 3 = 法律意见书 | 1 = 申报版 |
| I0051 | 5 = 发行保荐书 | 1 = 申报版 |
| I0061 | 6 = 上市保荐书 | 1 = 申报版 |

所以：

- `I0022` = 审计报告的上会版；
- `I0033` = 法律意见书的注册版；
- `I0052` = 发行保荐书的上会版；
- `I0063` = 上市保荐书的注册版。

### 3. 对于 `I10xx`、`I20xx`、`I30xx`，后两位表示“子类型”

| fileTypeMap | 前两位 | 后两位 | 含义 |
|---|---|---|---|
| I1010 | 10 | 10 | 注册批复 |
| I1020 | 10 | 20 | 终止审核决定 |
| I2010 | 20 | 10 | 上市委会议公告 |
| I2020 | 20 | 20 | 上市委会议结果公告 |
| I3010 | 30 | 10 | 问询回复文件组 |

## 三、`fileType=None` 的含义

`fileType=None` 并不是“没有类别”，而是说明该组文件没有映射到固定的 `fileType` 数字编码。

从文件标题看，`I3010` 这一组实际是：

- `8-1`：发行人及保荐机构/中介机构对审核问询函的回复；
- `8-2`：会计师/申报会计师对审核问询函的回复；
- `8-3`：律师事务所补充法律意见书。

这些文件包含首轮问询回复、二轮问询回复、审核中心意见落实函回复、上市委意见落实函回复，以及财务数据更新版等。  
因此可以把 `I3010 + fileType=None` 理解为：**“审核问询阶段动态产生的多轮回复文件”**。

## 四、补充说明

从文件标题中的编号也能辅助判断类别：

| 标题编号前缀 | 对应文件类别 |
|---|---|
| 1-1 | 招股说明书 |
| 3-1-2 | 发行保荐书 |
| 3-1-3 | 上市保荐书 |
| 3-2-1 | 财务报告及审计报告 |
| 3-3-1 | 法律意见书 |
| 8-1 / 8-2 / 8-3 | 审核问询回复、会计师回复、补充法律意见书 |

因此，在使用时应同时关注 `fileTypeMap` 和 `fileType`：  
`fileType` 确定文件大类，`fileTypeMap` 进一步确定是申报稿、上会稿、注册稿，还是批复、终止决定、审议公告或问询回复。
