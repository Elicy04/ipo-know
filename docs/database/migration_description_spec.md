### Alembic 迁移描述命名规范（双下划线分隔版）
#### 一、核心规则
1. **分隔逻辑**：用**双下划线 `__`** 分隔「动作、表名、细节」三个层级；表名、字段名内部的原生命名保留单下划线，彻底解决标识符与分隔符混淆的问题。
2. **基础格式**：`动作前缀__表名__变更细节`，全小写，仅含字母与下划线，无空格、无特殊字符，完全兼容 Alembic 文件名生成规则。
3. **精简原则**：若变更主体不言自明，可省略第三段细节，缩减为 `动作前缀__表名`。

#### 二、标准动作前缀（统一复用，禁止自定义）
| 前缀   | 适用场景                                   |
|--------|--------------------------------------------|
| create | 新建数据表、Schema                         |
| drop   | 删除表、字段、索引、约束                   |
| add    | 新增字段、索引、约束、枚举值               |
| alter  | 修改字段属性（类型、空值、默认值、长度）   |
| rename | 重命名表、字段                             |
| data   | 纯数据操作（初始化、修复、补数）           |

#### 三、高频场景示例（含下划线表名，直观体现可读性优势）
1. **表级变更**
   - 新建用户信息表：`create__user_profile`
   - 删除废弃订单明细表：`drop__order_item_old`
   - 商品表重命名：`rename__goods_info__product_info`

2. **字段级变更**
   - 用户信息表新增手机号：`add__user_profile__mobile`
   - 订单表修改收货地址长度：`alter__order_main__address_length`
   - 删除冗余临时字段：`drop__user_profile__temp_field`

3. **索引与约束**
   - 新增邮箱唯一索引：`add__user_profile__email_unique`
   - 删除状态普通索引：`drop__order_main__status_idx`

4. **数据类变更**
   - 初始化字典数据：`data__init_dict`
   - 修复订单状态脏数据：`data__fix_order_status`

#### 四、命名禁忌
- 禁止模糊命名：禁用 `update`、`fix`、`v2` 等无追溯价值的描述
- 禁止混用分隔符：不得用单下划线替代层级分隔，不得出现三连下划线
- 禁止过度冗长：字段具体类型、长度等细节无需写入，点到为止
- 禁止多主题混杂：单次迁移只对应一类核心变更

#### 五、自动化生成适配建议
1. 同表多字段变更：统一概括为 `alter__xxx_table__multi_fields`，无需罗列所有字段
2. 跨表批量微调：可按主变更表命名，或统一使用 `alter__multi_tables__batch_update`
3. 长度控制：自动生成时对细节段做截断，总长度建议控制在 40 字符内，避免文件名过长
4. 模块可选：多业务线项目可在最前加模块前缀，如 `user__create__user_profile`
